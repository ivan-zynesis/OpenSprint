# DS-AGENTIC-SDLC: Power an Entire Engineering Team, Human or Agent

## Statement

Software development becomes real engineering only when the detail across **dev, sec and ops** is all taken care of. OpenSprint exists to power an entire engineering team at that standard — **regardless of whether the participants are human or agent** — and at a scale beyond what a single change workflow addresses.

## Rationale

The premise has not changed since the project started: **code became cheap.**

Connecting context and building the knowledge base are the load-bearing activities in software engineering now. Where every detail of the context is recorded, rebuilding a whole application from it is easy. Generating the code was never the hard part; knowing what it must do, what must stay true of it, why it was built that way, and how it is run — that is the part that was always thrown away.

This is a **different ambition from OpenSpec's, not a correction of it.** Running a quick change against a brownfield project is well served by OPSX and still is. OpenSprint is the larger claim: that the same discipline, applied across every accountability a team carries, makes an engineering organisation that agents can participate in without the reasoning being lost.

The move is deliberately away from vibe coding. Not because generating code quickly is wrong, but because a system nobody can explain is not engineered, whoever or whatever wrote it.

## Implications

- The unit of concern is the **team's whole output**, not one change: functional intent, non-functional bars, application code and infrastructure alike
- An agent is a first-class participant, so every artifact is written to be read by one
- Scale is a requirement rather than an aspiration — see [[DS-PARALLEL-EXEC]]
- What this deliberately does **not** reach is recorded in [[DS-SURROGATE-SCOPE]]
