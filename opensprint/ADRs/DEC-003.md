# DEC-003: DFS Traversal Order — Initiative → ADRs → Active Changes

## Question

In what order should citizens be evaluated during universe reconciliation?

## Decision

Traverse depth-first: for each initiative in the source universe, evaluate all ADRs referenced by or created during that initiative, then evaluate all active opsx changes belonging to that initiative. The initiative is the unit of commitment — if any inner node produces an unresolved conflict, the entire initiative pauses for operator judgment before the DFS continues to the next initiative.

## Consideration Factors

- **Dependency coherence**: an opsx change may depend on ADRs created during the same initiative; evaluating ADRs first ensures change evaluation has correct context
- **Atomic commitment**: partial migration of an initiative (some ADRs migrated, some changes dropped) produces an incoherent surrogate state
- **Operator cognitive load**: pausing at initiative boundaries (not at every inner node) keeps operator confirmation prompts grouped and meaningful

## Citizen Classification

Each citizen is classified as one of:

| Class | Meaning | Action |
|---|---|---|
| MIGRATE | Compatible, adds value to target universe | Auto-migrate if high confidence, else confirm |
| CONFLICT | Contradicts target universe's decisions | Pause, present to operator |
| REDUNDANT | Target universe already has equivalent | Skip |
| SUPERSEDED | Target universe resolved this differently | Drop, record in manifest |

## Invalidation Trigger

If initiative-level pausing proves too coarse (very large initiatives with many inner conflicts), sub-initiative checkpointing can be introduced.
