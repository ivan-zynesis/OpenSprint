# DEC-017: The Surface Is the CLI Plus Generated Agent Files — No GUI, No CI/CD

## Question

OpenSprint has no graphical interface and ships no pipeline of its own. Is that a gap to close, or a decision to record?

## Decision

A decision, and it stands. The product surface is the `opensprint` CLI plus the skill and command files it generates into a downstream project. There is no GUI, and the tool ships no CI/CD product.

## Consideration Factors

| Factor | Weight | CLI plus generated files | Adding a GUI or a pipeline product |
|---|---|---|---|
| Fits the operator | HIGH | The operator already lives in a terminal beside an agent ✓ | A second surface to context-switch into ✗ |
| Speed of evolution | HIGH | A workflow change is a template edit ✓ | Every change needs a UI counterpart ✗ |
| Competitive exposure | HIGH | Nothing here a provider would bother replicating ✗/✓ | Competes directly with better-resourced tooling ✗ |
| Surface area to maintain | HIGH | One surface, 26 tool adapters behind it ✓ | Two surfaces, both needing backward compatibility ✗ |
| Discoverability | MED | Requires reading docs ✗ | A GUI teaches itself ✓ |

## Rationale

[[DS-SELF-USE-SCOPE]] settles this. A tool built to be evolved quickly for our own use cannot also carry a graphical surface that must be redesigned every time a workflow changes. The agent *is* the interface: the generated skill files are what an operator actually interacts with, and they are text because the consumer is a language model.

The absence of a CI/CD product is the same reasoning from the other direction. OpenSprint orchestrates work inside someone else's repository, and that repository already has a pipeline. Shipping one would mean owning a deployment story for projects we do not control.

The honest cost is discoverability, and it is accepted rather than dismissed: the tool is harder to pick up than a GUI would make it, which is why the documentation burden in [[DS-SELF-USE-SCOPE]] is stated as a requirement rather than an aspiration.

## Invalidation Trigger

If OpenSprint acquires users outside the team who cannot be onboarded through documentation alone, discoverability stops being an accepted cost and this decision should be re-argued. Adoption by people we do not talk to is the signal.
