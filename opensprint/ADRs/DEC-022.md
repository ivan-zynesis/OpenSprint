# DEC-022: `/opsp:attest` Is a Separate Tool, Not a Phase of Compact

## Question

Attestation produces posture, evidence and exposure against a bar ([[DS-MEASURE-ANATOMY]]). Compact already runs after archive and already reads every record. Should attestation be a phase of compact, or its own tool?

## Decision

A new tool, `/opsp:attest`, sitting between `/opsp:apply` + `/opsp:review` and `/opsp:archive`.

| | |
|---|---|
| **reads** | the initiative's bars, the changes shipped, the rules, test and scan artifacts |
| **asks the operator** | for each bar — met? by what evidence? what remains exposed? |
| **writes** | `### Posture`, `### Evidence`, `### Exposure` into the record's `## Measures` |
| **never** | blocks, gates, promotes or approves ([[DEC-023]]) |

It is human-in-the-loop by design.

## Consideration Factors

| Factor | Weight | Separate tool | A phase of compact |
|---|---|---|---|
| Preserves the deterministic/synthetic split | HIGH | Compact stays re-runnable without a model ✓ | Puts a HITL judgement inside the compile engine ✗ |
| Honours "compact never writes a record" | HIGH | Attest writes; compact still does not ✓ | Breaks [[DEC-006]] directly ✗ |
| Lifecycle legibility | HIGH | Attestation is a visible stage ✓ | A critical stage hidden inside a compile ✗ |
| Re-runnable in CI | MED | Compact unchanged ✓ | Compact becomes interactive ✗ |
| Tool surface area | LOW | One more skill ✗ | No new skill ✓ |

## Rationale

The intuitive objection is right and there is a principled reason underneath it. `architecture.md` names the deterministic/synthetic split load-bearing: grouping, hashing, staleness and gating live in code so they can be verified without a model, and condensing prose lives in a skill. Attestation is neither. It is a **human judgement that produces a new fact**, and it needs an artifact and a person, not a model and not a hash.

[[DEC-014]] made compact the single compile engine, and a compile derives — it states what the records already imply. Attestation **discovers**: nothing in the record set determines whether a bar was met. Putting it inside compact would mean the one engine whose entire value is model-free re-runnability could no longer be re-run without a human present, which also breaks its use as a CI gate under [[DEC-010]].

[[DEC-006]] settles the rest: compact never writes a record. Attest must write to records, because posture, evidence and exposure belong inside the goal they qualify ([[DEC-019]]). A tool that writes records is simply not compact — it is the same category as `/opsp:decide` and `/opsp:driver`.

Placing it before archive rather than after follows from [[DS-ATTESTED-TRUTH]]: nothing can be documented that has not been attested, and archive is what compiles the documentation.

## Invalidation Trigger

If attestation turns out to be fully derivable from rule outcomes and test artifacts with no human judgement required, it is a compile step after all and belongs back inside compact.
