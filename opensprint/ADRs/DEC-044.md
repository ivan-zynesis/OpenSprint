# DEC-044: Attest Gains a Second Write Target — the Documentation Directory

## Question

[[DEC-027]] bounds `/opsp:attest` to a record's `## Measures` and nothing else, because a record's
claim must never change under a reader who cited it. [[DS-DOCUMENTATION-REVIEWED]] now requires it to
produce and improve an external-facing account. Does the bound loosen?

## Decision

**The bound on records does not move.** Attest still writes only `## Measures` inside a record,
checked by `checkAmendment`.

What is added is a **second, separate write target**: the project's documentation directory, where
attest may write freely.

```
  TARGET                  WHAT ATTEST MAY DO              CHECKED BY
  ──────────────────      ────────────────────────────    ──────────────
  a record                `## Measures` only              checkAmendment
  the initiative          `## Attestation` only           the same bound
  docs/ (configurable)    anything — it is prose          nothing
```

The directory is `docs/` by default and configurable in `openspec/config.yaml`:

```yaml
docsDir: docs/internal
```

Attest **urges** rather than writes silently: it produces the account in context, asks the operator
where it belongs, and writes only on confirmation.

## Consideration Factors

| Factor | Weight | Second target, records unchanged | Widen the record bound | Never write docs |
|---|---|---|---|---|
| A record's claim stays stable | HIGH | Untouched ✓ | Erodes [[DEC-006]] ✗ | ✓ |
| The external account gets written | HIGH | Yes ✓ | Yes ✓ | Stays a conversation that ends ✗ |
| The bound stays checkable | HIGH | `checkAmendment` unchanged ✓ | A looser bound checks less ✗ | ✓ |
| Prose is not over-constrained | MED | Docs are free-form ✓ | ✓ | — |
| Write surface grows | LOW | A whole directory ✗ | ✗ | None ✓ |

## Rationale

Loosening the record bound would have been the obvious move and the wrong one. The bound exists so
that **a claim never changes under a reader who cited it** — and that guarantee is worth more than
the convenience of one tool writing in one more place.

A documentation directory is a different kind of target entirely. Nothing cites it by id, nothing
compiles from it, and no agent loads it to make a decision. It is prose for people, so the
constraints that protect records do not apply and would only get in the way.

Making it configurable follows [[DS-SQUAD-HATS]]'s reasoning about hats: where a project's
documentation lives is a property of the project. A repository already publishing from
`documentation/` or `docs/internal/<hat>` says so once.

**Urging rather than writing silently** is the part that matters in practice. The operator decides
what an external reader should be told — attest only guarantees the question is asked and the answer
lands somewhere durable rather than in a conversation nobody will reopen.

The accepted cost: nothing checks what lands there. An account that drifts from what shipped will
not fail a build the way a compiled view does, and only the next attestation will notice.

## Invalidation Trigger

If the documentation directory accumulates content that other tooling begins to parse or cite, it
has become a record in everything but name and needs the protections of one. The first time
something reads `docsDir` expecting structure is the signal.
