# DEC-026: `BOARD.md` Is a Compiled Sibling of `DECISION-MAP.md`

## Question

Tracking initiative and milestone state in practice required an in-repo board. [[DS-FORWARD-CLOSURE]] needs a roadmap for exposures to point into. Is the board a hand-maintained kanban, a squad view, or something else?

## Decision

`opensprint/BOARD.md` — **compiled**, by the same `/opsp:compact` pass, from initiative state, milestone completion and change status. It is a sibling of `DECISION-MAP.md`: cross-cutting rather than hat-scoped, and therefore not a squad view.

It has two halves:

- **doing / next** — initiatives by state, with their milestones
- **roadmap** — forward-looking work, and **every open exposure beside the state of what mitigates it**

Because it is compiled, **moving a card means changing a record's state**. The board is never edited.

## Consideration Factors

| Factor | Weight | Compiled board | Hand-maintained kanban | External tracker |
|---|---|---|---|---|
| Cannot drift from reality | HIGH | Derived; `compact check` gates it ✓ | Drifts the day it is created ✗ | Drifts ✗ |
| Honours [[DEC-006]] | HIGH | Never hand-edited ✓ | Hand-edited by definition ✗ | N/A ✗ |
| Travels with the code | HIGH | In the worktree, per [[DEC-001]] ✓ | In the worktree ✓ | Outside; universes cannot fork it ✗ |
| Exposures resolve to live state | HIGH | `mitigated-by` renders its target's state ✓ | Manual ✗ | Manual ✗ |
| Suits non-engineer readers | MED | Markdown in a repository ✗ | Same ✗ | Purpose-built ✓ |

## Rationale

The board is not a detour from documentation — it is the missing render. It derives entirely from state already held in records, which makes it legitimately a compile output rather than a parallel source of truth. [[DEC-006]]'s rule holds without strain: if the board is wrong, the system is wrong, and the fix is a record's state, not a text editor.

Placing it beside `DECISION-MAP.md` rather than in `squad/` follows the existing precedent. `DECISION-MAP.md` is already a generated, cross-cutting artifact that belongs to no single hat, and the board has exactly that shape. A squad view answers "what must be true for my hat"; the board answers "where is everything", which is nobody's hat and everybody's question.

The roadmap half is what makes [[DS-FORWARD-CLOSURE]] mechanical. Rendering an exposure next to the live state of its `mitigated-by` target turns a static risk list into a gradient of assurance — *we know and are thinking* reads differently from *committed, with a bar*, and a reader can tell them apart without opening anything. A new harvest rule, `exposure-unmitigated`, reports the exposures pointing nowhere.

It depends on [[DEC-024]], since nothing can be rendered by state until initiatives have one.

## Invalidation Trigger

If the board needs any field that is not already derivable from record state, that field belongs on the record and the board stays derived — never the reverse. If non-engineer readers cannot use markdown in a repository, that is a publishing question about output surface, deliberately deferred, not a reason to hand-maintain the board.
