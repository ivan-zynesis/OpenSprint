# DEC-021: `attested` Is a Third Citation Authority

## Question

[[DEC-009]] gives a compiled claim two possible citations: a record id where a decision established it, a path where it was observed from the system. [[DS-ATTESTED-TRUTH]] requires a third thing — that a human asserted it true with evidence. Does that fit the existing two, or is it a new authority?

## Decision

A third authority is added. A compiled claim may cite:

| Authority | Citation form | Licenses |
|---|---|---|
| **decided** | a record id | "we decided X" |
| **observed** | a path | "the system does X" |
| **attested** | evidence ref · date · attester | "X is true, as of then" |

Only **attested** licenses an unqualified present-tense claim about a property of the system. A compiled view must visibly distinguish the three, and an attestation carries a date so staleness is computable.

## Consideration Factors

| Factor | Weight | Third authority | Extend `observed` | Leave at two |
|---|---|---|---|---|
| Distinguishes intent from reality | HIGH | Directly ✓ | Conflates a human assertion with a file path ✗ | Not at all ✗ |
| Honesty of compiled output | HIGH | Present tense is earned ✓ | Partially ✓ | Decided claims read as facts ✗ |
| Staleness is computable | HIGH | Carries a date ✓ | A path has no date ✗ | — |
| Change to existing records | MED | None; purely additive ✓ | None ✓ | None ✓ |
| Reader burden | LOW | Three authorities to learn ✗ | Two ✓ | Two ✓ |

## Rationale

[[DEC-009]] already reasons that decided and observed *"carry different authority — a decision binds, an observation may be an accident."* The gap it did not anticipate is that **a decision that binds may also simply not be true yet**, and the compiler has no way to say so.

This project's own output demonstrates it. `architecture.md` states *"Operator-only reconciliation — absolute, not a preference"* under **Constraints & Non-Negotiables**, which reads as a property of the running system. `squad/maintainer.md`, compiled in the same pass from the same records, says *"the guardrail is instruction text in a skill, which no rule reads."* Neither is wrong. The compiler had no third category.

Folding attestation into `observed` was rejected because an observation is a path — reproducible, model-free, undated. An attestation is a human judgement against an artifact at a point in time. Collapsing them would cost the one property that makes attestation safe: it visibly ages, and a reader can tell when it was last true.

That ageing is the known weakness and it is accepted deliberately. An attestation that has gone stale is a far better failure mode than a claim that was never verified at all.

## Invalidation Trigger

If attestations age faster than they are renewed across the board, the authority is decorative and the compile should degrade stale attestations to `decided` rather than continuing to render them as fact.
