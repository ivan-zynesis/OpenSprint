# DEC-001: Universes Are Git Worktrees — Surrogate Stays In Place

## Question

How do parallel initiatives maintain independent surrogates without custom storage mechanisms?

## Decision

Each git branch/worktree IS a universe. The `opensprint/` directory lives in its branch as-is and travels with the code. No copying, no special universe storage layer, no synchronization daemon.

## Consideration Factors

- **Git worktree isolation**: each `git worktree add` produces a fully independent directory tree — `opensprint/` diverges naturally as commits accumulate on the branch
- **Simplicity**: no new storage abstraction; git history already captures surrogate evolution
- **Tooling alignment**: existing `git diff`, `git log`, and merge tooling apply to surrogate files directly

## Rationale

Git's worktree model already provides exactly the isolation needed. Introducing a separate "universe registry" or surrogate copy mechanism would add complexity without benefit. The surrogate should be treated like source code — versioned, branched, and merged through git.

## Invalidation Trigger

If surrogate files grow too large for git's line-diff model to handle meaningfully (e.g., architecture.md becomes a multi-thousand-line document), a binary or structured-diff approach may be warranted.
