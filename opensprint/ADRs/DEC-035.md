# DEC-035: Initiative States Gain `declined`

## Question

[[DEC-024]] runs an initiative `exploring -> proposed -> building -> attested -> completed`. A real backlog accumulates candidates, and most of them die. There is no exit for an idea that was considered and dropped.

## Decision

Add **`declined`** as a terminal state, set by `/opsp:triage` ([[DEC-039]]). A declined initiative keeps its Objective and Goal and records why it was declined.

`declined` is terminal but not permanent: a declined candidate may be revived by triage, which returns it to `exploring`.

The state-versus-git check treats `declined` as resolved and stops reporting it.

## Consideration Factors

| Factor | Weight | A `declined` state | Delete the file | Leave it `exploring` |
|---|---|---|---|---|
| The board stays readable | HIGH | Filterable ✓ | ✓ | Dead items crowd live ones ✗ |
| The check stops nagging | HIGH | Terminal ✓ | Nothing to nag about ✓ | Flagged forever ✗ |
| The reasoning survives | HIGH | Recorded ✓ | Lost ✗ | Implicit, unstated ✗ |
| The same idea does not return | MED | Visible when it does ✓ | Returns unrecognised ✗ | ✓ |
| `main` stays clean | LOW | Declined items accumulate ✗ | ✓ | ✗ |

## Rationale

Without a terminal state, `initiatives/` becomes a graveyard of permanently-`exploring` records, and the state-versus-git check flags every one of them forever — which trains the operator to ignore the check, losing the mechanism that catches real dangling.

Deleting the file is the obvious alternative and loses the most valuable part. **Why an idea was declined is worth more than the idea.** The same proposal returns six months later, and a record saying "declined because the licensing cost exceeded the saving" ends that conversation in a minute. [[DEC-029]] already accepts declined candidates living on `main`; this makes the acceptance explicit and useful.

Revivability matters because declining is a judgement made under conditions that change. Returning a candidate to `exploring` rather than creating a fresh one keeps its history, including the earlier decline and its reason.

## Invalidation Trigger

If declined items accumulate to the point that the board is unreadable, the answer is board filtering or archival, not deletion — the reasoning must survive either way.
