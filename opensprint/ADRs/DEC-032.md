# DEC-032: Evidence Is a CI Artifact Reference; the Pipeline Exemption Rides the Next Initiative

## Question

[[DEC-019]] gives a measure an `### Evidence` block. What may go in it, and how is a bar attested when it genuinely cannot be assessed before merging — a change to the pipeline itself?

## Decision

**An `### Evidence` block references an artifact produced by a pipeline run** — a coverage report, a recorded end-to-end run, a `terraform plan`, a cost diff, a scan result — addressable from the pull request. Prose describing a belief is not evidence.

An evidence reference that does not resolve is **harvested**, not assumed good.

**The pipeline exemption**: a bar that cannot be assessed pre-merge is attested `posture: pending`, with an exposure naming why. It is re-attested **by the next initiative that touches the area**, from the runs that have since accumulated. It never earns a pull request of its own.

## Consideration Factors

| Factor | Weight | CI artifact reference | Free prose | Dedicated follow-up PR |
|---|---|---|---|---|
| Checkable | HIGH | Resolves or does not ✓ | Unfalsifiable ✗ | — |
| Non-engineer can use it | HIGH | Watch the recording, read the report ✓ | Trust the author ✗ | — |
| Commit history stays clean | HIGH | — | — | A PR containing only attestation ✗ |
| Exemption cannot widen | HIGH | No mechanism to abuse ✓ | — | A convenient path, so it will widen ✗ |
| Pending bars eventually close | MED | Opportunistically; may linger ✗ | — | Immediately ✓ |

## Rationale

Defining evidence as a pipeline artifact is what makes [[DS-CI-ATTESTATION]]'s bet operational. A bar assessed from prose is assessed from an opinion, and the whole purpose of attestation is to be more than that. It also makes the evidence half mechanically checkable, which converts a reviewer's diligence into a harvest rule.

Giving the exemption no pull request of its own is what stops it becoming a habit. A named exception with a stated reason and **no convenient mechanism** behaves differently from one with a ready path: there is nothing to reach for, so the only way to close a pending bar is to do work in that area, which is when the evidence exists anyway.

The accepted cost is that a pending attestation can linger indefinitely. It is a harvested open loop and a visible board row, so it nags by visibility rather than by gating — consistent with [[DEC-023]]. Lingering is reported, which is the most this system is willing to do about it.

## Invalidation Trigger

If pending attestations routinely outlive several initiatives, visibility is not enough and the pending bar needs an owner and a date rather than a pull request. If teams start classing ordinary work as pipeline work to reach the exemption, the exemption needs a narrower definition.
