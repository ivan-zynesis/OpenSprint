# DEC-040: Attest Reads the Tests — Never the Source, the Design or the Rationales

## Question

[[DEC-033]] excluded the entire implementation from the attester's context, on the reasoning that an
agent holding the diff rationalises. Practice says that is right about the risk and wrong about the
artifact: with only a bar and a CI artifact, an attester cannot tell a suite that *ran* from a suite
that *asserted the bar*.

## Decision

The reading scope becomes:

```
  LOADS                               DOES NOT LOAD
  ------------------------------      -----------------------------
  initiative Objective + Goals        the implementation source
  the bars (given / when / then)      the design discussion
  the test files                      the ADR rationales
  maintainer rows in scope            the conversation that built it
  CI evidence artifacts
```

Test files are in. The implementation source, the design discussion and the decision rationales stay
out. This supersedes [[DEC-033]].

Where there are no tests covering a bar, the outcome is `cannot assess` — unchanged.

## Consideration Factors

| Factor | Weight | Tests in, source out | Nothing but CI artifacts ([[DEC-033]]) | Full diff |
|---|---|---|---|---|
| Attester stays at bar altitude | HIGH | A test *is* a bar restated ✓ | ✓ | Source is a different altitude ✗ |
| Catches a suite that asserts nothing | HIGH | Yes ✓ | **No — invisible** ✗ | Yes ✓ |
| Resists rationalisation | HIGH | "Does this assert the bar?" is falsifiable ✓ | Nothing to rationalise from ✓ | "This looks reasonable" ✗ |
| Works without a mature pipeline | HIGH | Tests are in the repo ✓ | Needs CI artifacts ✗ | ✓ |
| Preserves the CI incentive | MED | No tests → cannot assess ✓ | ✓ | Diff substitutes for both ✗ |
| Can diagnose a near-miss | LOW | Partially ✓ | No ✗ | Yes ✓ |

## Rationale

**A test is the implementation's own restatement of a bar.** [[DEC-038]] writes a maintainer bar as
`given / when / then`, which is test syntax. Comparing a bar to its tests compares two statements at
the same altitude; comparing a bar to source compares across altitudes, and that asymmetry is the
mechanism by which an attester talks themselves into a pass.

So this is not a widening of [[DEC-033]]'s context. It is a correction of **which artifact belongs
inside it** — and the original was excluding the one implementation artifact written in the bar's own
language.

It also closes a hole. A CI artifact proves a test ran; a test file shows what it asserted. A green
suite that never touches the bar satisfied the old rule completely, which is the most common way a
measure is met on paper and not in fact.

Rationales stay out for [[DEC-033]]'s reason, which did not move: an ADR argues *for the chosen
mechanism*, so loading it shifts the question from "was the bar met" to "was the mechanism
reasonable" — and the second question has a different owner.

**The accepted cost is that some self-assessment risk returns**, because the agent that wrote the
tests is often the one asked to attest. It is lower than with source, and it is why [[DEC-043]]
hardens the refusal to attest in the authoring session rather than relaxing it.

## Invalidation Trigger

If attesters routinely report `cannot assess` because tests exist but are unreadable without the
source, the altitude argument has failed and the scope needs rethinking — not quietly widening. If a
project's tests are generated from the bars themselves, reading them proves nothing and this
decision is circular.
