# DEC-023: Attest Writes a Record and Never Gates

## Question

[[DS-SURROGATE-SCOPE]] places certification, change management and release management out of scope, reasoning that *"certification alone drags in the other two."* `/opsp:attest` asserts that a bar was met, with evidence. That is one short step from certification. Where is the line?

## Decision

**Attest writes a record stating what is true, with evidence. It never decides whether that is good enough.**

Specifically, `/opsp:attest`:

- always exits zero; it has no pass/fail status
- never blocks `/opsp:archive`, a merge, a release or any other operation
- never marks an initiative "approved", "signed off" or "released"
- records an unmet bar as an exposure with a forward pointer, not as a failure

The compiled board and views **render** attestation state. Nothing **acts** on it.

## Consideration Factors

| Factor | Weight | Writes only | Gates on unmet bars |
|---|---|---|---|
| Honours the scope boundary | HIGH | Stays inside the surrogate ✓ | Becomes certification; drags in change and release management ✗ |
| Consistent with compact | HIGH | "Renders and reports" ✓ | compact gates on *drift*, not on *outcomes* — different thing ✗ |
| Operator retains judgement | HIGH | The record informs; the human decides ✓ | The tool decides ✗ |
| Catches a missed bar automatically | MED | No — a human must read ✗ | Yes ✓ |
| Audit usefulness | MED | An honest dated record ✓ | A gate that will be bypassed ✓/✗ |

## Rationale

[[DS-SURROGATE-SCOPE]] states that compaction *"renders and reports rather than approving, gating or promoting."* Attest inherits that posture exactly, and the inheritance is what keeps the scope boundary intact while still closing the loop.

The distinction is between **recording a fact** and **acting on it**. "The bar was not met; here is the exposure; here is what will mitigate it" is a statement about the world and belongs in the surrogate. "Therefore you may not ship" is a release management decision, requires an approver with authority, an appeals path and an audit trail of overrides — which is precisely the cascade [[DS-SURROGATE-SCOPE]] predicted.

[[DEC-010]]'s `compact check` is not a counter-example. It fails the build when a compiled view **disagrees with its records** — an internal consistency check on derived output. It has never gated on whether the system is good enough, and this decision keeps that line where it is.

The accepted cost is real: a missed bar will sit in a record until someone reads it. [[DS-FORWARD-CLOSURE]] is the mitigation — an exposure with no `mitigated-by` pointer is harvested as an open loop, so the gap surfaces through the backlog rather than through a gate.

This constraint is recorded now, before the tool is built, precisely because it is the kind of boundary that erodes one convenience at a time.

## Invalidation Trigger

If this project ever needs real certification — an external auditor, a signed attestation with legal weight — that is a scope change to [[DS-SURROGATE-SCOPE]] itself, decided deliberately, not a feature added to attest. The first pull request adding an exit code to this tool is the signal.
