# DEC-004: Mandatory Planning Phase Before Execution

## Question

How should high-impact reconciliation operations gate themselves before making changes?

## Decision

Both `/opsp:rebase` and `/opsp:abandon` open with a read-only planning phase that produces a conflict manifest before touching any files. The operator reviews the manifest and explicitly confirms before execution begins.

## Planning Phase Contents

1. Load surrogates from both worktrees
2. Diff driver-specs, ADRs, initiatives, and active changes
3. Pre-classify all citizens per DEC-003 taxonomy
4. Produce conflict manifest: counts of MIGRATE / CONFLICT / REDUNDANT / SUPERSEDED citizens
5. Warn operator: "This operation is recommended to run with the most capable available model and extended thinking enabled"
6. Surface cross-skill recommendation if applicable: "High ADR divergence detected — did you mean `/opsp:abandon` instead of `/opsp:rebase`?"
7. Show estimated scope: N ADRs, M changes, K conflicts requiring operator input
8. Wait for operator confirmation

## Consideration Factors

- **Irreversibility**: both operations mutate the canonical surrogate; there is no undo short of git reset
- **Scope surprises**: operators may not know how far two universes have diverged until they see the manifest
- **Wrong-command guard**: deep architectural divergence during a rebase attempt is a signal the operator may have intended abandon instead

## Invalidation Trigger

If planning phase becomes slow for very large surrogates, a fast-path pre-scan (count-only, no classification) can be offered before the full manifest.
