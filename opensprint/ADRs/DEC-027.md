# DEC-027: Record Amendment Is a Third Write Mode

## Question

`/opsp:attest` writes posture, evidence and exposure into the `## Measures` section of an **existing** record ([[DEC-019]]). Every tool so far either creates records or derives artifacts. What is amendment, and how does it interact with the manifest?

## Decision

Amendment is recognised as a **third write mode**, distinct from the two that exist:

| Mode | Tools | Touches |
|---|---|---|
| **create** | `/opsp:decide`, `/opsp:driver`, `/opsp:propose` | a new record |
| **derive** | `/opsp:compact`, `/opsp:archive` | compiled artifacts only; never a record ([[DEC-006]]) |
| **amend** | `/opsp:attest` | a named section of an existing record |

An amendment is **additive and bounded**: it writes only within `## Measures`, never rewrites a Statement, Rationale or Decision, and never alters frontmatter other than appending attestation metadata. Amending a record restages every section whose input hash includes it, exactly as creating one does — the manifest treats an amended record as changed.

## Consideration Factors

| Factor | Weight | Amendment as its own mode | Attest creates new records | Attest edits freely |
|---|---|---|---|---|
| Attestation attaches to its measure | HIGH | Inside the goal it qualifies ✓ | A measure and its attestation in two files ✗ | ✓ |
| Bounded blast radius | HIGH | One named section ✓ | New file; none ✓ | Any record, any section ✗ |
| Manifest correctness | HIGH | Amended record restages its sections ✓ | New record restages ✓ | Same ✓ |
| Honours [[DEC-006]] | HIGH | compact still writes no record ✓ | ✓ | ✓ |
| Reviewability of the diff | MED | A section-scoped diff ✓ | A whole new file ✓ | Unbounded diff ✗ |

## Rationale

Naming the mode is the point. Until now the system had a clean rule — tools that create records, and one engine that derives and never writes records — and attestation does neither. Leaving it unnamed would mean the first tool to modify an existing record does so without anyone having decided what that is allowed to touch.

Bounding it to `## Measures` is what keeps [[DEC-006]]'s guarantee meaningful. The source of truth for *what was decided* stays immutable in practice: attest cannot revise a Decision or a Statement, so a record's claim never changes under a reader who cited it. What it adds is a different kind of content — what turned out to be true about that claim — in a section reserved for it.

The manifest interaction needs no new machinery. [[DEC-010]] hashes record content per section input; an amended record simply hashes differently and restages the sections that consume it, which is correct — a view asserting a bar is unverified must restage once it has been attested.

[[DS-HIGH-IMPACT-OPS]] does not apply. That constraint governs operations that mutate the canonical surrogate with unbounded blast radius. An additive, section-bounded amendment by an operator-invoked HITL tool is neither unbounded nor automatic.

## Invalidation Trigger

If attest ever needs to modify a Decision, a Statement or a Rationale, that is a new decision superseding an old one — `/opsp:decide`'s job — not an amendment. The first request to widen amendment beyond `## Measures` should be refused and recorded.
