## Context

`DEC-026` makes the board a compiled sibling of `DECISION-MAP.md`. Milestones 4 and 5 supplied everything it needs.

## Goals / Non-Goals

**Goals**
- Compile every initiative into a board, grouped by state
- Surface the state check and orphaned milestones where someone will see them
- Leave a place for exposures to land

**Non-Goals**
- `mitigated-by` and the exposure gradient — milestone 10
- A kanban UI — deferred explicitly by the operator; the compiled markdown is enough until the states are real
- Cross-branch listing — recorded as blocking on `sdlc-operating-contract`, unsolved

## Decisions

### Generated by code, not by the skill

Every other compiled artifact splits deterministic staging from synthetic condensation, because prose needs a model. The board needs none: it is structured state rendered as a table, and a model in the loop would add a way for it to be wrong. So it follows `DECISION-MAP.md` — pure code, regenerated rather than sealed.

That also keeps it out of the manifest. `compact check` gates artifacts where a skill could disagree with its sources; there is no skill here to disagree.

### Grouped by state, not by hat

The board answers "where is everything", which is nobody's hat and everybody's question. `DS-BIG-PICTURE` governs hat views; this is the other kind of artifact, and `DECISION-MAP.md` already set the precedent for a cross-cutting generated file at the top level.

### Problems are on the board, not only in a command

`checkInitiativeState` and `orphanedMilestones` both report things that make a board wrong — an initiative that cannot be placed, a milestone that is not counted. Printing them only from a command would mean the board quietly disagrees with reality while looking complete. They go on the board itself.

### The roadmap section exists before it has content

`DS-FORWARD-CLOSURE` makes the roadmap the forward half of the board, and it is where exposures land. Those need `mitigated-by`, which milestone 10 adds. An empty section that names what is coming is better than one that appears later — the reader learns the shape once.

## Risks / Trade-offs

**The board shows only the current branch.** `DEC-029` was reversed on contact with practice, so every initiative lives on its own branch from birth, backlog items included. No branch sees them all — which is recorded as blocking in `sdlc-operating-contract` and is not solved here.

**Regenerating on `seal` means the board changes when views are sealed**, even if no initiative moved. Accepted: the file is deterministic, so an unchanged board regenerates byte-identical and produces no diff.

## Migration Plan

None. The board is new and is generated from existing initiatives.
